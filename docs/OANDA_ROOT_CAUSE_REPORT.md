# OANDA Root-Cause Report

## Executive result

The OANDA integration is not authenticated, and account-specific pricing is not configured. OANDA rejected the configured practice token with HTTP **401**. The EUR/USD H1 candle request returned **0 candles**. The running API independently reports OANDA `INVALID_CREDENTIALS` and no configured OANDA account ID.

No genuine candle, bid/ask quote, open-position valuation, or live P&L could be verified. The dashboard must continue to show market data as unavailable and disable operations that require a fresh quote. No real-money orders were placed.

## Root causes and evidence

### OANDA authentication

One authenticated request was made to the official practice endpoint:

`GET https://api-fxpractice.oanda.com/v3/instruments/EUR_USD/candles?granularity=H1&count=100&price=M`

The request used OANDA v20 Bearer authentication; the credential was not printed or recorded.

- **OANDA response:** HTTP **401**
- **Sanitized response body:** `Insufficient authorization to perform request.`
- **Candles returned:** **0**
- A second single request using the exact requested H1/count-10 URL without an explicit `price` parameter also returned HTTP **401**, with the same sanitized OANDA error and **0** candles.
- **Selected environment/host:** `practice` / `https://api-fxpractice.oanda.com`
- **Configuration:** `OANDA_API_TOKEN` is present in the backend configuration. `OANDA_ACCOUNT_ID` is absent.
- In a clean Node process, there was no inherited `OANDA_API_TOKEN`; dotenv loaded the token from `apps/api/.env`. The value had no leading/trailing whitespace or surrounding quotation marks, was 36 characters, and UUID-shaped. OANDA's 401 establishes it is not accepted at the selected practice endpoint; the response cannot differentiate wrong token type, revocation, or account/environment mismatch.
- The 401 proves OANDA rejected the bearer credential for this request. It does not distinguish a wrong token type, revoked token, or token/environment mismatch.
- The Nest environment loader reads `apps/api/.env` before bootstrapping the application. The running backend health response confirms that the process has an OANDA token configured for practice, but the exact source cannot be proven from the status endpoint because inherited environment variables take precedence and secret values are intentionally never returned.

The backend's unauthenticated health endpoint returned HTTP **200** and reported `configured: true`, environment `practice`, `accountIdConfigured: false`, and provider/candle/quote status `INVALID_CREDENTIALS`. `apps/api/src/main.ts` loads the environment before Nest starts, and `apps/api/src/config/env-loader.ts` resolves `apps/api/.env`. The health response confirms the running process has OANDA configuration, but intentionally does not reveal the token or its source. Dotenv does not override inherited process variables; therefore, the health endpoint alone cannot prove that a pre-existing process variable did not override the `.env` token.

### Candles, quotes, and account configuration

- OANDA's `/v3/instruments/{instrument}/candles` request is implemented independently of `OANDA_ACCOUNT_ID`. Unit tests verify the EUR/USD H1 mapping, chronological normalized OHLC output, and account-independent candle request.
- The live candle request failed during authentication, so normalized candles did not reach the backend market API or TradingView Lightweight Charts. Chart rendering with genuine live data remains unverified.
- Account-specific pricing requires the actual OANDA account ID. It is not the application's internal `TRD-...` account ID. No OANDA account ID was invented or substituted.
- No account-specific Bid/Ask request was made because the OANDA account ID is missing and the token is rejected.
- Existing position valuation uses a genuine close-side quote when available: BUY positions are marked at bid and SELL positions at ask. If no fresh quote exists, valuation and P&L remain unavailable; entry prices, candle closes, and simulated prices are not substituted.

### Application HTTP 503

The browser's margin/P&L 503 is generated by the application, not by OANDA. The request reaches `TradingEngineV2Controller.getMarginInfo()` and `MarginService.calculateAccountMargin()`. With open positions but no fresh quote, the service cannot calculate margin, equity, or unrealized P&L and returns a structured OANDA quote-unavailable response. This is separate from OANDA's upstream HTTP 401.

The margin error now preserves the underlying category where known (including invalid credentials, missing account ID, account access denial, rate limiting, network failure, and unsupported instrument) and reports whether retrying is appropriate. The authenticated margin endpoint also checks that the requesting user owns the trading account.

The OANDA provider now retains a bounded, sanitized upstream error message and HTTP status category in its safe diagnostic text. The restarted backend health endpoint reports `OANDA rejected the token (HTTP 401): Insufficient authorization to perform request.` without including credentials.

The application's candle API was probed without an application JWT and correctly returned HTTP **401 Unauthorized**. The candles route is behind `JwtAuthGuard`; no user token was available for an authenticated end-to-end candle request. The health endpoint is reachable and confirms the provider's live status. No auth guard was bypassed or weakened to force a candle request.
