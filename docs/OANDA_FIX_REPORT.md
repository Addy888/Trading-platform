# OANDA Fix Report

## Outcome and verified root cause

The practice OANDA token configured by the backend environment loader is rejected by OANDA. A direct request using that environment's effective token was made to:

`GET https://api-fxpractice.oanda.com/v3/instruments/EUR_USD/candles?granularity=H1&count=10`

The request used the OANDA v20 Bearer authorization scheme. The token was never printed or written to this report.

- **HTTP status:** `401`
- **Sanitized upstream response:** `Insufficient authorization to perform request.`
- **Candles:** `0`
- **Selected OANDA environment:** `practice`
- **OANDA account ID:** not configured

The `apps/api/.env` loader ran in a clean process with no inherited `OANDA_API_TOKEN`; the loaded token came from that file. It had no surrounding whitespace or quotes and was UUID-shaped (length 36). OANDA rejected it for the practice endpoint. The HTTP response cannot distinguish a wrong token type, revoked token, or token/environment mismatch. Use an active OANDA personal access token intended for the practice environment. The separate running backend health response also returned HTTP `200` and reported OANDA configured for practice with `INVALID_CREDENTIALS`; it does not reveal secret values.

The 503 seen on the browser's margin request is generated by the application when an open position cannot be valued without a fresh quote. It is not OANDA's response. `GET /api/market/candles` was also probed without an application JWT and returned HTTP `401 Unauthorized`, as required by `JwtAuthGuard`. No authentication control was bypassed. Without a valid application session token, an authenticated backend candle response could not be tested.

- `apps/api/src/trading-engine/margin.service.spec.ts` — covers owner authorization and categorized quote failure.
- `apps/api/src/trading-engine/balance-equity.service.spec.ts` — corrects precision assertions and financial-state mocks.
- `docs/OANDA_ROOT_CAUSE_REPORT.md` — detailed root-cause evidence and verification.
- `docs/OANDA_FIX_REPORT.md` — this report.

The backend startup credential check now probes this exact account-independent EUR/USD H1/count-10 candle endpoint. Candle retrieval remains independent of `OANDA_ACCOUNT_ID`, completed OHLC candles are normalized, the frontend retains Lightweight Charts, and BUY exits use bid while SELL exits use ask. Those paths have automated test coverage, but live data flow is blocked by the rejected credential.

## Quote, position, and margin status

- **Bid/Ask availability:** unavailable. No pricing call can be made safely without the actual OANDA account ID, and the configured token is rejected.
- **Open-position current price and unrealized P&L:** not verifiable live; no genuine fresh quote was received. The application does not replace missing prices with entry prices, candle closes, or generated values.
- **Margin:** unavailable for open positions until genuine fresh quotes arrive. The application returns an explicit, categorized failure rather than a success-shaped valuation.
- **Orders:** remain gated on valid fresh bid/ask data and existing risk checks. No order was placed.
- The app's internal trading-account ID must not be used as `OANDA_ACCOUNT_ID`.

Replace or confirm `OANDA_API_TOKEN` with an active OANDA personal access token for the selected practice environment, and configure the actual account ID belonging to that same environment as `OANDA_ACCOUNT_ID` in the ignored `apps/api/.env`.
