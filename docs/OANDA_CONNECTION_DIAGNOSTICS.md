# OANDA Connection Diagnostics

## Current result

The OANDA integration is not connected. On 2026-10-21, one authenticated request was made to the official practice endpoint:

`GET https://api-fxpractice.oanda.com/v3/instruments/EUR_USD/candles?granularity=H1&count=100&price=M`

The request used the value loaded from `apps/api/.env` with an OANDA v20 `Authorization: Bearer ...` header. The credential was not printed or included in this report.

**Observed response:** HTTP **401**; sanitized OANDA response: `Insufficient authorization to perform request.` Candle count: **0**.

Configuration diagnostics (values only, not the secret):

- Backend env file: `apps/api/.env`, resolved through `apps/api/src/config/env-loader.ts`.
- Token: present; no leading/trailing whitespace or wrapping quotes detected in the `.env` value.
- Token format: UUID-shaped. This is not enough to prove credential type, but OANDA rejected it when sent as a bearer token.
- Environment: `practice`; host selected: `https://api-fxpractice.oanda.com`.
- `OANDA_ACCOUNT_ID`: absent.
- No inherited `OANDA_API_TOKEN` or `OANDA_ENVIRONMENT` was present in the diagnostic process before loading the `.env`, so the one request used the file's value. The loader uses dotenv's default non-overriding behavior; a separately launched backend process with inherited environment variables can still override values from `.env`.

The 401 is evidence that OANDA rejected the token at the configured practice host. It does not identify whether the value is not an OANDA personal access token, is revoked, or belongs to another environment. Configure a valid personal access token created for the intended OANDA practice environment; do not bypass authentication or switch environments automatically.

## Historical candles, account pricing, and order safety

- OANDA's instrument-candles endpoint is account-independent. `OandaProvider.getTimeSeries()` calls `/v3/instruments/{instrument}/candles` without requiring `OANDA_ACCOUNT_ID`. The provider's unit tests verify EUR/USD H1 normalization, chronological output, and candle retrieval without an account ID. The live request failed at authentication, so no genuine candles reached the backend endpoint or Lightweight Charts.
- `OANDA_ACCOUNT_ID` is required for account-specific instruments and pricing. It must be the actual OANDA account ID associated with the same environment and token. Never use the app's internal trading account ID.
- Bid/ask quotes, open-position valuation and P&L are unavailable until OANDA authentication, the actual OANDA account ID, and a fresh quote are available.
- New orders remain disabled in the dashboard without a valid, fresh bid/ask quote. Backend order placement independently checks quote freshness, bid/ask execution price, account ownership, margin, and risk rules. No orders were placed.

## Why the browser sees HTTP 503

The 503 is generated by the application, not by the OANDA request. The browser's margin call is:

`GET /api/v2/trading-accounts/:accountId/margin`

It reaches `TradingEngineV2Controller.getMarginInfo()` and `MarginService.calculateAccountMargin()`. When an open position has no fresh market tick, the service throws NestJS `ServiceUnavailableException` (HTTP 503), because it cannot calculate margin/equity/P&L from a valid close-side price. This is separate from OANDA's direct **401** candle-authentication response.

The 503 body now identifies provider `OANDA`, code `OANDA_QUOTE_UNAVAILABLE`, and a category identifying the underlying blocker where known (for example `INVALID_CREDENTIALS` or `ACCOUNT_ID_REQUIRED`). It does not substitute an entry price, candle close, internal account ID, or simulated quote.
