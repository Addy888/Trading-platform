PROJECT: Trading Dashboard - Twelve Data API Rate Limiting Issue
STATUS: ✅ COMPLETE AND VERIFIED

================================================================================
PROBLEM
================================================================================

The trading dashboard was exceeding Twelve Data API rate limits (HTTP 429) and
displaying blank charts to users. Root cause was not rate limiting itself, but
the application making 80% more API requests than necessary.

Error Message:
  [loadCandles] Error: RATE_LIMITED: Twelve Data rate limited the request.
  File: apps/web/app/dashboard/trading/[accountId]/page.tsx
  Line: 668

================================================================================
ROOT CAUSES IDENTIFIED (6)
================================================================================

1. Frontend Polling Effect Triggered on Dependency Changes
   → Each symbol/timeframe change restarted polling, causing duplicate requests
   → File: apps/web/app/dashboard/trading/[accountId]/page.tsx:700

2. No Request Deduplication
   → Multiple simultaneous requests for same symbol/timeframe were allowed
   → File: apps/web/app/dashboard/trading/[accountId]/page.tsx:loadCandles()

3. Polling ALL Symbols Instead of Selected One
   → Quote polling fetched 5 symbols but only 1 was displayed
   → File: apps/web/hooks/useMarketQuotes.ts:33

4. Short Cache TTL vs Long Polling Interval
   → Cache: 5 min | Polling: 15 min → Cache always expired before next poll
   → File: apps/api/src/market-data/market-data-manager.service.ts:34

5. Broken Cache Eviction
   → LRU eviction didn't use actual timestamp comparison
   → File: apps/api/src/market-data/market-data-manager.service.ts:cached()

6. Cache Key Inconsistency
   → Empty string vs missing exchange could create different keys for same data
   → File: apps/api/src/market-data/market-data-manager.service.ts:185

================================================================================
SOLUTION IMPLEMENTED (7 CHANGES)
================================================================================

1. Backend: Extended Cache TTL
   ✅ 300ms → 1,800ms (5 min → 30 min)
   ✅ Ensures every 15-min poll hits cache
   ✅ File: apps/api/src/market-data/market-data-manager.service.ts:34

2. Backend: Fixed Cache Eviction
   ✅ Proper LRU using timestamp comparison
   ✅ Prevents memory bloat, keeps frequently-used data
   ✅ File: apps/api/src/market-data/market-data-manager.service.ts:cached()

3. Backend: Consistent Cache Keys
   ✅ Use 'NONE' instead of empty string for missing exchange
   ✅ Same request = same cache key always
   ✅ File: apps/api/src/market-data/market-data-manager.service.ts:185

4. Frontend: Stable Polling Effect
   ✅ Use refs instead of dependency array to prevent effect restart
   ✅ Polling continues uninterrupted on symbol/timeframe change
   ✅ File: apps/web/app/dashboard/trading/[accountId]/page.tsx:690-730

5. Frontend: Request Deduplication
   ✅ Track in-flight requests, skip duplicates
   ✅ Added candleInFlightRef to prevent simultaneous duplicate requests
   ✅ File: apps/web/app/dashboard/trading/[accountId]/page.tsx:loadCandles()

6. Frontend: Selective Quote Polling
   ✅ Only fetch selected symbol instead of all 5
   ✅ 80% fewer quote API calls
   ✅ File: apps/web/hooks/useMarketQuotes.ts:33

7. Frontend: Better Error Handling
   ✅ Preserve chart data on rate limit
   ✅ Show friendly message "Request limit reached. Please wait..."
   ✅ File: apps/web/app/dashboard/trading/[accountId]/page.tsx:catch block
